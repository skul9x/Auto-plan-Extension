## 3. PHÂN TÍCH NGUYÊN NHÂN GỐC RỄ (Root Cause Analysis)

Sau khi đối chiếu mã nguồn (`src/bridgeServer.ts`, `src/promptDispatcher.ts`, `media/autoplan-dom-bridge.js`), có **3 nguyên nhân kết hợp** dẫn đến lỗi này:

### 🔴 Nguyên nhân 1: Cơ chế Client Stale Timeout (30 giây) làm rớt Client
- Trong `src/bridgeServer.ts`:
  ```typescript
  export const DEFAULT_STALE_CLIENT_MS = 30000; // 30 giây
  ```
- Từ lúc client probe thành công (`13:06:48`) đến lúc Dispatcher kiểm tra readiness (`13:07:24`) là **36 giây**.
- Trong khoảng 36 giây này, nếu người dùng chưa bấm chạy ngay hoặc tab/window Electron bị unfocus / idle khiến Renderer giảm tần suất gửi HTTP request, hàm `getActiveClients()` và `runWatchdogCheck()` đã tự động **xóa client khỏi danh sách (Eviction)** vì vượt quá ngưỡng 30s (`> 30000ms`).
- Khi client bị xóa, `connectedClientsCount` tụt về `0`.

### 🔴 Nguyên nhân 2: Cấu hình "Strict Mode" khóa cứng Tier 1, cấm hoàn toàn Fallback
- Cấu hình hiện tại của bạn:
  - `Dispatch Execution Mode`: **`domBridge`**
  - `Allow Tier Fallback`: **`false`** (Tắt fallback)
  - `Strict Execution Mode`: **`true`**
- Trong `src/promptDispatcher.ts`:
  ```typescript
  if (allowFallback === false && mode !== 'auto') {
    if (mode === 'domBridge') {
      if (connectedClientsCount > 0) {
        return { ready: true, ... };
      } else {
        return {
          ready: false,
          errorMessage: 'Strict Tier 1 (DOM Bridge) requires active Electron bridge injection.'
        };
      }
    }
  }
  ```
- Do bật chế độ **Strict Mode** và tắt Fallback, khi DOM Bridge bị ngắt tạm thời (0 clients), Extension **ngay lập tức dừng và quăng lỗi đỏ** thay vì tự động chuyển sang Tier 2 (Command API) hoặc Tier 3 (`xdotool` trên Linux).

### 🔴 Nguyên nhân 3: BridgeServer bị khởi động lại hoặc Extension Reload
- Dữ liệu `Bridge Server Active Listening Port: None (Server Inactive)` ở mục 1 cho thấy sau khi fail readiness check, server socket đã bị close hoặc extension bị trigger reload khiến state bị reset.

## 5. HƯỚNG DẪN KHẮC PHỤC (Step-by-Step Fix)

### Cách 1: Khắc phục ngay trên giao diện (Không cần sửa code)
1. **Mở Settings Panel:**
   - Bấm `Ctrl+Shift+P` (hoặc `F1`) gõ: **`Auto-Plan: Open Settings Panel`**.
2. **Bật chế độ linh hoạt (Auto / Fallback):**
   - Chuyển **Execution Mode** từ `DOM Bridge (Strict)` sang **`Auto (Tier 1 -> Tier 2 -> Tier 3)`** hoặc bật switch **`Allow Tier Fallback` = `ON`**.
   - Điều này đảm bảo dù DOM Bridge có bị lag/idle thì Auto-Plan vẫn chạy mượt qua Tier 2/Tier 3 mà không bao giờ bị dừng.
3. **Reload Window để Client kết nối lại:**
   - Bấm `Ctrl+Shift+P` gõ: **`Developer: Reload Window`**.
   - Kiểm tra dưới thanh Status Bar thấy pill: `Auto-Plan: Bridge: Online (Port 48860)` và `Clients: 1`.

---

### Cách 2: Tối ưu mã nguồn (Đã thực hiện trong Extension)
1. **Tăng `DEFAULT_STALE_CLIENT_MS`:** Tăng ngưỡng timeout từ `30000ms` lên `60000ms` hoặc `120000ms` để tránh bị evict khi IDE ở trạng thái idle/chờ người dùng bấm lệnh.
2. **Client Heartbeat Keep-Alive:** Bổ sung interval gửi heartbeat ping đều đặn 10 giây/lần trong `media/autoplan-dom-bridge.js` kể cả khi không có command nào được gửi.
3. **Auto-Reconnection trong Readiness Check:** Trước khi báo lỗi `connectedClientsCount: 0`, Dispatcher tự động kích hoạt 1 nhịp phát hiện nhanh (fast-probe) để đánh thức renderer client nếu server đang mở.
