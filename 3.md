# Báo cáo Phân tích Lỗi & Hướng dẫn Khắc phục: Auto-Plan Extension v1.0.5 trên Linux

---

## 1. Tóm tắt Hiện tượng & Lỗi trong ảnh

Khi cài đặt và kích hoạt extension `antigravity-auto-plan-1.0.5.vsix` trên Linux và bấm bắt đầu tự động hóa, Antigravity IDE xuất hiện thông báo cảnh báo màu vàng:

```text
⚠️ Auto-Plan: DOM Bridge & Native Commands unavailable. Falling back to OS Keyboard Simulation.
Source: Antigravity Auto-Plan Runner
```

### 🔴 Kết quả thực tế:
1. Giao diện hiển thị cảnh báo trên và status bar thông báo đang gửi prompt.
2. Tuy nhiên, **khung chat Antigravity hoàn toàn đứng im**, không có phím tắt nào được kích hoạt, prompt không được dán vào khung chat và không có tin nhắn nào được gửi đi.
3. Tiến trình chuyển sang trạng thái chờ đợi vĩnh viễn (`Waiting for conversation...`) và sau **15 phút** sẽ văng lỗi **Timeout Error**.

---

## 2. Phân tích Chi tiết Nguyên nhân Gốc rễ (Root Cause Analysis)

Trong phiên bản **v1.0.5**, extension đã được nâng cấp kiến trúc điều phối gửi prompt đa tầng (**3-Tier Fallback Transport Chain**) trong file `src/promptDispatcher.ts`. Kiến trúc này hoạt động theo thứ tự ưu tiên giảm dần:

```mermaid
flowchart TD
    Start([Bắt đầu gửi Prompt]) --> T1{Tier 1: DOM Bridge\n(Electron Renderer IPC)}
    T1 -- Thành công --> Done([✅ Gửi Prompt thành công & Focus-Free])
    T1 -- Thất bại (Chưa Inject / Chưa Reload / Quyền Root) --> T2{Tier 2: Native Command\n(antigravity.sendTextToChat)}
    T2 -- Thành công --> Done
    T2 -- Thất bại (Command không tồn tại) --> T3[Tier 3: OS Keyboard Simulation\n(PowerShell / Linux Input)]
    T3 --> Warn[⚠️ Hiện thông báo Warning như trong ảnh]
    Warn --> CheckOS{Kiểm tra OS}
    CheckOS -- Windows --> PS[Gửi qua PowerShell SendKeys]
    CheckOS -- Linux --> Fail[❌ keyboardManager bỏ qua vì process.platform !== win32]
    Fail --> Hang[⏳ Treo 15 phút -> Timeout Error]
```

### 🔍 Chi tiết từng tầng thất bại:

### 1️⃣ Tier 1 (DOM Bridge) thất bại vì sao?
- **Cơ chế**: Extension Host tạo một HTTP Bridge Server (port dải `48860` - `48900`). Đồng thời, một thẻ `<script src="autoplan-dom-bridge.js"></script>` cần được chèn vào file `workbench.html` của Antigravity IDE. Khi IDE khởi động, script này trong Electron Renderer sẽ tự động kết nối (heartbeat) về Extension Host.
- **Nguyên nhân thất bại trên Linux**:
  1. **Quyền hạn tập tin (Linux File Permissions)**: Thư mục cài đặt của VS Code / Antigravity IDE trên Linux (thường nằm tại `/usr/share/antigravity/`, `/usr/share/code/`, hoặc `/opt/...`) thuộc quyền sở hữu của người dùng `root`. Khi người dùng cài file `.vsix`, extension **không có quyền ghi mặc định** vào file `workbench.html`.
  2. **Chưa kích hoạt cài đặt hoặc chưa Reload Window**: Ngay cả khi extension có cơ chế `pkexec` (hộp thoại nhập mật khẩu root), nếu người dùng chưa chạy lệnh cài đặt Bridge hoặc **chưa thực hiện Reload Window** (`Developer: Reload Window`), tiến trình Renderer vẫn là phiên bản cũ chưa tải file `autoplan-dom-bridge.js`.
  3. **Kết quả**: `bridgeServer.getConnectedClients().length === 0` (không có renderer DOM nào kết nối). Do đó Tier 1 ném ra lỗi: `DOM Bridge has no active connected clients`.

---

### 2️⃣ Tier 2 (VS Code Native Command API) thất bại vì sao?
- **Cơ chế**: Extension dự phòng việc gọi lệnh nội bộ `vscode.commands.executeCommand('antigravity.sendTextToChat', promptText)`.
- **Nguyên nhân thất bại**: Lệnh `antigravity.sendTextToChat` là một command dự trù, **chưa được đăng ký hoặc không tồn tại** trong Antigravity IDE / VS Code. Khi thực thi, VS Code văng lỗi `command 'antigravity.sendTextToChat' not found`. Do đó Tier 2 tiếp tục thất bại.

---

### 3️⃣ Rơi xuống Tier 3 (OS Keyboard Simulation) và xuất hiện Popup cảnh báo
- Khi cả Tier 1 và Tier 2 đều trả về lỗi trong chế độ `mode: 'auto'`, file `src/promptDispatcher.ts` thực thi đoạn mã:
  ```typescript
  // Trích từ src/promptDispatcher.ts (Dòng 256-258)
  this.warningNotifier(
    'Auto-Plan: DOM Bridge & Native Commands unavailable. Falling back to OS Keyboard Simulation.'
  );
  ```
- **Hậu quả tiếp theo trên Linux**:
  Hàm `dispatchTier3` gọi `keyboardManager.executeBatchPromptFlow()`. Tuy nhiên trong `src/keyboardManager.ts`:
  ```typescript
  // Trích từ src/keyboardManager.ts (Dòng 284-297)
  if (process.platform === 'win32') {
    // Chạy PowerShell SendKeys
    const psCommand = `powershell -NoProfile -NonInteractive -Command "${batchScript}"`;
    await execAsync(psCommand);
  } else {
    // Trên Linux: KHÔNG LÀM GÌ, chỉ in cảnh báo ra log
    console.warn(`KeyboardManager: executeBatchPromptFlow called on non-Windows platform: ${process.platform}`);
  }
  ```
  Tiến trình kết thúc giả lập phím mà không gửi bất kỳ thao tác nào, cửa sổ chat không nhận được prompt, dẫn đến việc `transcriptWatcher` chờ 15 phút rồi báo lỗi **Timeout**.

---

## 3. Hướng dẫn Khắc phục Chuẩn xác (Step-by-Step Fix)

Để Auto-Plan Extension hoạt động trơn tru trên Linux với đầy đủ tính năng **Focus-Free** (vừa chạy tự động vừa thoải mái lướt web/làm việc khác), hãy làm theo các bước sau:

### 🛠️ Bước 1: Cấp quyền sở hữu thư mục cài đặt Antigravity trên Linux

Mở Terminal trên Linux và chạy lệnh phân quyền cho user hiện tại (thay đổi đường dẫn phù hợp với nơi cài đặt Antigravity / VS Code):

```bash
# Trường hợp Antigravity được cài đặt trong /usr/share/antigravity:
sudo chown -R $(whoami) /usr/share/antigravity

# Hoặc nếu là bản build dựa trên VS Code tiêu chuẩn (/usr/share/code):
sudo chown -R $(whoami) /usr/share/code

# Hoặc nếu nằm trong /opt:
sudo chown -R $(whoami) /opt/antigravity
```

> **Giải thích kỹ thuật**: Lệnh này giúp VS Code / Antigravity có quyền sửa đổi file `workbench.html` và chèn script DOM Bridge mà không bị chặn bởi quyền `root` (EACCES).

---

### 🛠️ Bước 2: Kích hoạt cài đặt DOM Automation Bridge

1. Mở Antigravity IDE.
2. Nhấn tổ hợp phím **`Ctrl + Shift + P`** (hoặc `F1`) để mở **Command Palette**.
3. Gõ và chọn lệnh:  
   👉 **`Auto-Plan: Install / Update DOM Automation Bridge`** (`autoplan.installBridge`).
4. Khi xuất hiện hộp thoại thông báo thành công, bấm chọn **`Reload Window`** (hoặc mở Command Palette chọn `Developer: Reload Window`).

---

### 🛠️ Bước 3: Kiểm tra Trạng thái kết nối (Bridge Diagnostics)

Sau khi Reload Window, hãy kiểm tra xem DOM Bridge đã kết nối thành công chưa:

1. Nhấn **`Ctrl + Shift + P`**.
2. Gõ và chọn: 👉 **`Auto-Plan: Check Bridge Status & Run Diagnostic`**.
3. Hộp thoại chẩn đoán sẽ hiển thị các thông tin sau:
   - `DOM Bridge Script:` **✅ Installed**
   - `Workbench File:` **[Đường dẫn tới workbench.html]**
   - `Bridge Server:` **✅ Running (Port: 48860)**
   - `Connected DOM Clients:` **1** (hoặc lớn hơn 0)
   - `Transport Mode:` **auto** (hoặc **domBridge**)

*(Nếu thấy `Connected DOM Clients: 1`, nghĩa là DOM Bridge đã hoạt động hoàn hảo)*.

---

### 🛠️ Bước 4: Chạy thử tính năng Tự động hóa

1. Mở một workspace có thư mục `plans/`.
2. Bấm vào nút **`$(rocket) Auto-Plan`** ở góc phải dưới thanh Status Bar (hoặc bấm `Ctrl + Shift + P` -> `Auto-Plan: Start Automation`).
3. Chọn Phase cần thực thi.
4. Prompt sẽ được **bắn trực tiếp vào khung Chat thông qua DOM nội bộ mà không cần chiếm Focus màn hình hay gửi phím ảo**. Bạn có thể thu nhỏ IDE và tiếp tục lướt web bình thường.

---

## 4. (Tùy chọn) Khắc phục Cảnh báo "Your installation appears to be corrupt"

Khi chỉnh sửa file `workbench.html`, VS Code / Antigravity IDE có thể hiển thị thông báo góc phải dưới:  
`"Your Code installation appears to be corrupt. Please reinstall."`

### Cách xử lý:
- Đây là cơ chế kiểm tra toàn vẹn mã nguồn (checksum integrity check) mặc định của VS Code.
- Extension `Auto-Plan` đã tích hợp sẵn hàm cập nhật checksum `updateProductChecksums()`.
- Nếu vẫn thấy cảnh báo xuất hiện:
  1. Bấm vào biểu tượng **Bánh răng (Settings)** trên góc thông báo cảnh báo đó.
  2. Chọn **"Don't Show Again"**.

## 5. Bảng So sánh Trạng thái Trước và Sau khi Sửa

| Tiêu chí | Trước khi sửa (Khi bị lỗi như ảnh) | Sau khi cấu hình DOM Bridge thành công |
| :--- | :--- | :--- |
| **Cơ chế gửi Prompt** | Rơi về Tier 3 (PowerShell - Bị vô hiệu hóa trên Linux) | Chạy qua Tier 1 (DOM Bridge IPC qua `autoplan-dom-bridge.js`) |
| **Thông báo Warning** | ⚠️ Xuất hiện popup vàng cảnh báo fallback | ❌ Không còn warning, chạy trực tiếp mượt mà |
| **Tương thích Linux** | ❌ Bị liệt, treo 15 phút -> Timeout Error | ✅ Hoạt động 100% trên Linux (Ubuntu, Debian, Fedora, Arch,...) |
| **Độc lập Focus** | ❌ Yêu cầu cửa sổ active | ✅ **Focus-Free**: Tự do lướt web, làm việc khác trong lúc AI chạy |
| **Tốc độ gửi Prompt** | Chậm (phải delay mở chat, chọn, paste, enter) | **Tức thì (< 100ms)** thông qua DOM injection |

---

## 6. Tổng kết

- Lỗi trong ảnh là do **DOM Bridge chưa được kết nối vào tiến trình Renderer của Antigravity IDE** trên Linux, khiến hệ thống phải fallback về cơ chế giả lập phím ảo OS (vốn chỉ hỗ trợ PowerShell trên Windows).
- Bằng cách **chạy `sudo chown` cho thư mục cài đặt** ➔ **chạy lệnh `Auto-Plan: Install / Update DOM Automation Bridge`** ➔ **`Reload Window`**, bạn sẽ kích hoạt thành công cơ chế DOM Bridge mạnh mẽ nhất, khắc phục triệt để lỗi và tận hưởng trải nghiệm tự động hóa hoàn toàn ngầm trên Linux.
