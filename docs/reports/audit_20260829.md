## 🔴 Triệu chứng Nguy Kịch (Critical Issues - Cần cấp cứu)

### 1. 🫀 Quét sâu DOM toàn diện không giới hạn (`querySelectorAll('*')`) trong Renderer Process
- **Vị trí:** [`media/autoplan-dom-bridge.js`](file:///home/skul9x/Desktop/Test_code/Auto-plan-Extension-main/media/autoplan-dom-bridge.js#L28-L54), [`media/autoplan-dom-bridge.js`](file:///home/skul9x/Desktop/Test_code/Auto-plan-Extension-main/media/autoplan-dom-bridge.js#L361-L415)
- **Triệu chứng & Hậu quả (Huyết áp tăng vọt):** 
  - Hàm `queryDeep` duyệt qua tất cả thẻ `*` trong DOM và đệ quy vào từng `shadowRoot`.
  - Bộ lắng nghe `MutationObserver` được gắn vào `document.body` và kích hoạt hàm quét này trên **mỗi đột biến DOM** (kể cả khi con trỏ chuột nhấp nháy, text editor cuộn, hoặc terminal in log).
  - VS Code Electron chứa hàng chục nghìn DOM element. Việc quét sâu `*` liên tục ngốn 80-100% CPU của Renderer Process, gây nóng máy, hao pin và làm IDE bị giật lag.
- **Phác đồ điều trị:**
  - **Giới hạn phạm vi (Scoping):** Chỉ quét trong container chat AI (`.interactive-session`, `div.chat-input`, modal dialogs) thay vì toàn bộ `document.body`.
  - **Throttling/Debounce:** Debounce lời gọi quét DOM (tối thiểu 300ms–500ms) khi có Mutation event.

### 3. 🛑 Chặn Main Thread Event Loop bằng I/O Đồng Bộ (`Sync File Operations`)
- **Vị trí:** [`src/planScanner.ts`](file:///home/skul9x/Desktop/Test_code/Auto-plan-Extension-main/src/planScanner.ts#L223-L270), [`src/extension.ts`](file:///home/skul9x/Desktop/Test_code/Auto-plan-Extension-main/src/extension.ts#L171-L224), [`src/sidebarProvider.ts`](file:///home/skul9x/Desktop/Test_code/Auto-plan-Extension-main/src/sidebarProvider.ts#L61)
- **Triệu chứng & Hậu quả (Tim ngừng đập tạm thời):**

  - Khi dự án chứa nhiều file hoặc nằm trên ổ đĩa mạng/HDD, VS Code Extension Host bị "đứng hình" tạm thời trong lúc chờ I/O hoàn tất.
- **Phác đồ điều trị:**
  - Chuyển các hàm quét sang bất đồng bộ (`fs.promises.readdir`, `fs.promises.stat`) kết hợp bộ nhớ đệm (In-Memory Cache).

### 4. 🔄 Xung đột Polling kép: `fs.watch` chạy song song với `setInterval(300ms)` dày đặc
- **Vị trí:** [`src/transcriptWatcher.ts`](file:///home/skul9x/Desktop/Test_code/Auto-plan-Extension-main/src/transcriptWatcher.ts#L498-L514), [`src/transcriptWatcher.ts`](file:///home/skul9x/Desktop/Test_code/Auto-plan-Extension-main/src/transcriptWatcher.ts#L630-L646)
- **Triệu chứng & Hậu quả (Lãng phí năng lượng):**
  - TranscriptWatcher vừa mở Native File System Watcher (`fs.watch`), vừa duy trì Polling timer mỗi 300ms liên tục `stat` file để kiểm tra kích thước.
  - Vòng lặp 300ms kiểm tra không ngừng nghỉ kể cả khi không hề có thao tác đọc ghi nào, làm tăng số chu kỳ CPU nhàn rỗi.
- **Phác đồ điều trị:**
  - Ưu tiên `fs.watch`, chỉ sử dụng polling với tần suất giãn cách hơn (1000ms - 1500ms) như một phương án Fallback khi watcher mất tín hiệu.

## 🟢 Đề Xuất Bồi Dưỡng (Suggestions - Tùy chọn nâng cao)
1. **Quản lý Cache bằng `vscode.workspace.createFileSystemWatcher`:** Tự động xóa cache plan folder khi có file `.md` được tạo mới hoặc chỉnh sửa thay vì dùng TTL 5s.
2. **Tối ưu bộ nhớ đệm Buffer Stream trong TranscriptWatcher:** Tái sử dụng Buffer cố định (`Buffer.allocUnsafe`) thay vì cấp phát động nhiều lần khi đọc chunk.
