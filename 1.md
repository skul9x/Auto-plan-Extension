# Báo cáo Phân tích & So sánh Cơ chế Hoạt động: Auto-Plan Extension vs. Zixfel Auto Click & Scroll

---

## 1. Trả lời câu hỏi trọng tâm

### ❓ Câu hỏi 1: Extension `Auto-plan-Extension-main` khi lướt web (cửa sổ trình duyệt che lên IDE) thì không hoạt động được đúng không?
> **ĐÚNG.** Khi người dùng lướt web hoặc cửa sổ IDE bị che khuất / mất Focus (không còn là cửa sổ làm việc chính trên màn hình), `Auto-plan-Extension` **chắc chắn không hoạt động được** hoặc sẽ **gửi nhầm toàn bộ phím tắt và nội dung prompt vào trình duyệt web**.

### ❓ Câu hỏi 2: Tại sao extension `zixfel.ag-auto-click-scroll-9.8.12` vẫn tự click, tự cuộn được bình thường ngay cả khi lướt web che kín IDE?
> Vì **hai extension này sử dụng hai cơ chế hoàn toàn khác nhau**:
> - `Auto-plan-Extension` dựa vào **mô phỏng phím bấm cấp Hệ điều hành (OS-Level Keyboard Simulation)** thông qua PowerShell `SendKeys`. Cơ chế này **bắt buộc** cửa sổ IDE phải đang được Focus ở tầng OS. Khi bạn lướt web, trình duyệt đang nắm Focus nên phím bị bắn sang trình duyệt.
> - `zixfel.ag-auto-click-scroll` sử dụng cơ chế **Inject trực tiếp JavaScript vào DOM của Electron (`workbench.html`)**. Script chạy nội bộ bên trong tiến trình Renderer của IDE và gọi hàm JavaScript `targetBtn.click()` cùng DOM `scrollTop`. Cơ chế này **hoàn toàn độc lập với OS Window Focus**, chạy ngầm bình thường dù IDE bị che khuất hay thu nhỏ.

## 2. Chi tiết cơ chế kỹ thuật của từng Extension

### 🔴 2.1. Auto-plan-Extension (`Auto-plan-Extension-main`)

#### A. Kiến trúc hoạt động
1. **Quét file Plan (`planScanner.ts`)**: Đọc các file phase trong thư mục `plans/`.
2. **Theo dõi kết quả (`transcriptWatcher.ts`)**: Quét file nhật ký hội thoại `.brain/.../transcript.jsonl` trên ổ đĩa.
3. **Gửi lệnh Prompt (`orchestrator.ts` & `keyboardManager.ts`)**: Để gửi một prompt vào Antigravity IDE, extension gọi `keyboardManager.executeBatchPromptFlow()`.

#### B. Phân tích mã nguồn gửi phím (`src/keyboardManager.ts`)
```typescript
// Trích xuất từ src/keyboardManager.ts
public buildBatchScript(options?: BatchPromptOptions): string {
  return [
    `$ws = New-Object -ComObject WScript.Shell;`,
    `$ws.SendKeys('^+l');`,               // Gửi phím Ctrl + Shift + L (mở cửa sổ chat mới)
    `Start-Sleep -Milliseconds ${focusDelay};`,
    `$ws.SendKeys('^a');`,                // Gửi phím Ctrl + A (chọn tất cả)
    `Start-Sleep -Milliseconds ${selectDelay};`,
    `$ws.SendKeys('^v');`,                // Gửi phím Ctrl + V (dán prompt từ clipboard)
    `Start-Sleep -Milliseconds ${pasteDelay};`,
    `$ws.SendKeys('{ENTER}');`            // Gửi phím Enter (gửi prompt)
  ].join(' ');
}
```

#### C. Lý do thất bại khi lướt web:
- Đối tượng COM `WScript.Shell.SendKeys` (hoặc `System.Windows.Forms.SendKeys`) trong Windows chỉ đẩy keystroke vào **Active Foreground Window** (cửa sổ đang được kích hoạt ở cấp OS).
- Khi bạn mở Chrome / Edge / Firefox để lướt web:
  - Phím `Ctrl+Shift+L` bị gửi vào trình duyệt.
  - Phím `Ctrl+A` bôi đen toàn bộ nội dung hoặc thanh địa chỉ của trình duyệt.
  - Phím `Ctrl+V` dán prompt của Auto-plan vào trình duyệt.
  - Phím `Enter` thực hiện tìm kiếm / submit form trên trình duyệt.
- IDE Antigravity không hề nhận được bất kỳ phím nào, cửa sổ chat không được mở, prompt không được gửi.
- Hơn nữa, trên các hệ điều hành **Linux / macOS**, code trong `keyboardManager.ts` có dòng kiểm tra `if (process.platform === 'win32')`, nên nếu chạy trên Linux/macOS nó thậm chí sẽ bỏ qua hoàn toàn và chỉ in log `console.warn`.

### 🟢 2.2. Zixfel Auto Click & Scroll (`zixfel.ag-auto-click-scroll-9.8.12`)

#### A. Kiến trúc hoạt động
1. **Can thiệp vào file lõi của IDE (`src/extension.js`)**:
   - Khi kích hoạt, extension tìm đường dẫn file `workbench.html` của VS Code / Antigravity IDE (bằng hàm `getWorkbenchPath()`).
   - Tự động chèn một thẻ `<script src="ag-auto-script.js"></script>` vào cuối file `workbench.html` (thông qua `installScript()`).
2. **Chạy script trực tiếp trong Renderer Process (`media/autoScript.js`)**:
   - `ag-auto-script.js` chạy bên trong Electron WebContents (DOM runtime của chính IDE).
   - Thiết lập các vòng lặp định kỳ (`setInterval`) và bộ quan sát thay đổi DOM (`MutationObserver`).
3. **Giao tiếp đồng bộ cấu hình qua HTTP Server nội bộ**:
   - Extension Host chạy một HTTP server nội bộ (port dải `48787` - `48850`) và file `ag-auto-config.json` để script DOM biết các nút cần bấm (`Allow`, `Always Allow`, `Run`, `Submit`, `Accept`,...).

#### B. Phân tích mã nguồn click và cuộn DOM (`media/autoScript.js`)
```javascript
// Trích xuất từ media/autoScript.js
// 1. Quét tìm các button trong DOM của Antigravity
buttons.forEach(function (btn) {
    var text = (btn.innerText || btn.textContent || '').trim();
    // Khớp mẫu với các từ khóa: Allow, Run, Submit, Accept...
    if (CLICK_PATTERNS.some(function (p) { return matchesPattern(text, p); })) {
        targetBtn = btn;
    }
});

// 2. Kích hoạt click bằng JavaScript API nội bộ (Không thông qua OS Input)
if (targetBtn) {
    targetBtn.click(); // Gọi trực tiếp method .click() của HTML Element
}

// 3. Tự động cuộn trang
scrollables.forEach(function (el) {
    el.scrollTop = el.scrollHeight; // Thay đổi thuộc tính cuộn trực tiếp trên DOM
});
```

#### C. Lý do zixfel vẫn hoạt động hoàn hảo khi lướt web:
- **Không cần OS Window Focus**: `targetBtn.click()` và `el.scrollTop = el.scrollHeight` là các API thuần của JavaScript chạy trực tiếp trên cây DOM.
- **Tiến trình Electron Renderer vẫn chạy**: Khi bạn chuyển sang lướt web, Antigravity IDE bị che khuất nhưng tiến trình Electron của nó vẫn hoạt động trong nền. Vòng lặp `setInterval` và `MutationObserver` trong `autoScript.js` vẫn liên tục bắt được các nút mới xuất hiện trong giao diện chat và kích hoạt `.click()` ngay lập tức.
- **Không ảnh hưởng đến bàn phím/chuột của người dùng**: Người dùng vẫn có thể gõ phím, lướt web, bấm chuột trên trình duyệt mà không hề bị xung đột hay cướp tiêu điểm (focus).

## 3. Bảng so sánh tổng hợp

| Tiêu chí | Auto-plan-Extension | zixfel.ag-auto-click-scroll |
| :--- | :--- | :--- |
| **Cơ chế thực thi** | Gửi phím ảo qua OS (`SendKeys` / PowerShell) | Inject JavaScript vào DOM của Electron (`workbench.html`) |
| **Tầng can thiệp (Layer)** | Tầng Hệ điều hành (OS Level) | Tầng Giao diện nội bộ (Renderer DOM Level) |
| **Yêu cầu Focus cửa sổ IDE** | **BẮT BUỘC** (Phải là Foreground Active Window) | **KHÔNG CẦN** (Chạy ngầm trong nền) |
| **Khi người dùng lướt web** | ❌ **Thất bại** (Gửi nhầm phím vào trình duyệt) | ✅ **Hoạt động bình thường** |
| **Độ ổn định khi đa nhiệm** | Dễ bị ngắt quãng, gõ sai khi user chạm phím/chuột | Độc lập, không bị ảnh hưởng bởi thao tác chuột/phím của user |
| **Hỗ trợ đa nền tảng OS** | Chỉ hỗ trợ Windows (do dùng PowerShell) | Hỗ trợ Windows, Linux, macOS |

## 4. Hướng nâng cấp cho Auto-Plan Extension (Khuyến nghị)

Để `Auto-plan-Extension` có thể tự động gửi prompt và điều phối các phase chạy ngầm mà **không cần giữ focus** (người dùng vừa lướt web vừa để extension tự chạy), có thể áp dụng 1 trong 2 hướng sau:

1. **Cách 1 - Tích hợp DOM Script Injection (Giống kiến trúc của Zixfel)**:
   - Inject một đoạn script nhỏ vào `workbench.html` để tìm textarea/input của chat Antigravity trong DOM, gán giá trị prompt và kích hoạt sự kiện gửi form bằng JavaScript nội bộ.
2. **Cách 2 - Sử dụng VS Code Extension API / Built-in Commands**:
   - Thay vì dùng `WScript.Shell.SendKeys` để ấn `Ctrl+Shift+L`, sử dụng lệnh nội bộ của VS Code / Antigravity (ví dụ `vscode.commands.executeCommand(...)`) để truyền prompt trực tiếp tới extension chat mà không qua clipboard và phím bấm vật lý của hệ điều hành.
